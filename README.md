# BioMLLM

**Can a frozen generalist MLLM gain medical competence by plugging in a frozen medical foundation model through a few learned perceptual tokens?**

## Idea

A generalist MLLM (Qwen-VL family, off the shelf) stays **frozen**. A frozen medical foundation model $E_S$ runs in parallel, and its features correct a small set of task tokens:

$$T_i = e_{\text{task}} + F_i^{MLLM} + \alpha\,P_\theta(F_i^{S}), \qquad F_i^S = E_S(I)_i$$

Only $e_{\text{task}}$, $P_\theta$, $\alpha$ and the task head are trained. The native visual tokens are never modified.

- **Dense perception:** one `[MASK]` token per patch, predicted in a single bidirectional pass (STAMP-style). Boxes are derived from masks.
- **VQA / report:** `[PERC]` tokens on a coarser grid, placed after the native visual tokens; generation reads them as context.

Each modality is a **plug-in package** `{frozen FM, P_θ, e_task, head}`. Deactivating it restores the base model bit-for-bit.

## Hypotheses

| | Hypothesis | Main evidence |
|---|---|---|
| H1 | With the MLLM frozen, expert-conditioned tokens beat the same tokens without an expert on segmentation, VQA and report, and recover a large share of fine-tuning gains at a fraction of the cost | Pareto: performance vs trainable params / GPU-hours |
| H2 | Modality packages are independent: adding one does not hurt other modalities or general abilities | package on/off tables (MMBench, MMStar, TextVQA) |
| H3 (analysis) | How much of the gain is *specialist* knowledge | C3 vs C2 vs C1 vs static, per task family |

**Phase 1:** MLLM frozen (default). **Phase 2:** light LoRA with and without expert, full FT as a cost reference.

## Comparison conditions (`condition=...`)

| id | `condition=` | Added term | Controls for |
|---|---|---|---|
| C0 | `c0_none` | — (same trainable task tokens / head) | **key baseline**: isolates the expert |
| ctrl | `ctrl_static` | α·P(learned image-independent map) | extra capacity without image signal |
| C1 | `c1_self` | α·P(F^MLLM) | extra capacity, no new information |
| ctrl | `ctrl_noise` | α·P(noise) | capacity fed with no signal |
| C2 | `c2_dinov2`, `c2_siglip` | α·P(F^generalist) | "any second encoder" |
| ctrl | `ctrl_rad_dino_random` | α·P(F^random-init specialist) | architecture without pretraining |
| **C3** | `c3_rad_dino`, `c3_biomedclip` | α·P(F^medical FM) | **method** |

At test time, `model.shuffle_features = True` pairs each image with another image's expert features.

## Ablation axes

| axis | override |
|---|---|
| injection | `injection=pre_llm` (sum into task tokens) / `post_llm` (before the head, LISA-like) / `prepend` (extra tokens, VPT-like) |
| projector | `projector=linear` / `mlp` / `cross_attn` / `local_cross_attn` (k×k window, ClinFusion-style) |
| gate | `gate=scalar` / `token` / `fixed`; `conditioner.native_drop=p` (stochastic drop of F^MLLM in training) |
| training budget | `train=frozen` (default) / `lora` (phase 2) / `full` (reference) |

## Positioning

| Line of work | Papers | Difference |
|---|---|---|
| MLLM segmentation tokens | LISA, PixelLM, STAMP/STAMPlus, SAMTok | tokens come from the MLLM alone; the MLLM is fine-tuned |
| Medical specialisation of the visual stream | FADA (distillation), ClinFusion (multi-encoder fusion) | modify or replace the native visual representation; costly training |
| Perception tokens | AURORA, Visual Perception Token | tokens generated by or steering the MLLM's own perception |
| Conditioned prompts | VPT, CoCoOp, PrAda | static or self-conditioned prompts, no independent expert |

**Ours:** a frozen, independent medical FM conditions task tokens *inside* the LLM, with a single interface for dense and text tasks. The native visual tokens are untouched and the MLLM is frozen, so modalities are modular.

## Quickstart

Data, Hugging Face cache, expert features and runs live on DUNE (`/raid/DATASETS/BioMLLMData`), mounted with sshfs because the NFS mount needs root:

```bash
scripts/mount_dune.sh          # sshfs mount on ~/dune_data (needs a passwordless ssh key for dune)
source scripts/env.sh          # BIOMLLM_DATA, BIOMLLM_FEATURES, BIOMLLM_RUNS, HF_HOME
```

On a machine where DUNE is already mounted (e.g. NFS), skip the sshfs step and point to it:

```bash
export BIOMLLM_ROOT=/path/to/DUNE/DATASETS/BioMLLMData   # e.g. /scratch/DUNE/DATASETS/BioMLLMData
source scripts/env.sh
```

Setting up a new GPU machine:

```bash
git clone <repo-url> BioMLLM && cd BioMLLM
python3 -m venv .venv
.venv/bin/pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128   # match the CUDA driver
.venv/bin/pip install -e ".[experts,dev]"
.venv/bin/python -c "import torch; print(torch.cuda.is_available())"
.venv/bin/pytest                                           # unit tests
BIOMLLM_INTEGRATION=1 .venv/bin/pytest tests/test_integration_experts.py   # real checkpoints (HF cache on DUNE)
```

```bash
pip install -e ".[dev]"                 # core + tests
pip install -e ".[experts,train,eval]"  # real experts / training

pytest
python scripts/probe_experts.py                                    # experiment 0, synthetic smoke run
python scripts/prepare_data/montgomery.py --src <MontgomerySet> --dst $BIOMLLM_DATA/montgomery
python scripts/probe_experts.py probe_data=montgomery_lungs experts=[dinov2,siglip,rad_dino,biomedclip]
python scripts/train.py +experiment=debug                          # toy model smoke run

# First H1/H2 evidence (real Qwen3-VL-4B, needs a GPU and the HF cache on DUNE)
python scripts/train_seg_c0_vs_c3.py mllm=qwen_vl condition=c0_none     train=seg_smoke +run_name=c0
python scripts/train_seg_c0_vs_c3.py mllm=qwen_vl condition=c3_rad_dino train=seg_smoke +run_name=c3
python scripts/probe_mlp_control.py                                   # capacity-matched control, no LLM
python scripts/train_vqa_c0_vs_c3.py mllm=qwen_vl task=vqa condition=c0_none     train=seg_smoke +run_name=vqa_c0
python scripts/train_vqa_c0_vs_c3.py mllm=qwen_vl task=vqa condition=c3_rad_dino train=seg_smoke +run_name=vqa_c3
```

## Status

- [x] Conditioner (projectors incl. local cross-attention, gates, prepend, native drop), controls (static, shuffle, noise), freeze policies, cost tracking, modality packages. Tested on the toy backbone.
- [x] Experiment 0 tooling: linear probe, segmentation metrics, Montgomery preparation.
- [x] Experiment 0 on real CXR data (ChestX-Det, real experts): `python scripts/probe_experts.py probe_data=chestx_det experts=[dinov2,siglip,biomedclip,rad_dino,qwen3vl_4b,rad_dino_random]`. RAD-DINO Dice 0.445 (linear probe); `rad_dino_random` (same architecture, random weights) Dice 0.059 -- confirms the gain is from medical pretraining, not architecture.
- [x] Qwen-VL adapter (`src/biomllm/models/mllm/adapters/qwen_vl.py`): Qwen3-VL-4B frozen, two-pass forward reusing `Qwen3VLModel`'s own KV-cache continuation (no hand-rolled M-RoPE). `task="seg"`: one `[MASK]` token per patch (STAMP-style dense head). `task="vqa"`: `[PERC]` tokens on a coarser grid (avg-pooled F^MLLM) as context before the question/answer text, teacher-forced LM loss.
- [x] Projector output is LayerNorm'd (no affine) before the gate scales it (`conditioning/projector.py`), so `alpha` is comparable across experts/projectors -- an unnormalised MLP projector can dwarf the native task-token term even at a small `alpha`, making the gate unreadable.
- [x] First H1/H2 evidence (`scripts/train_seg_c0_vs_c3.py`, `scripts/train_vqa_c0_vs_c3.py`, `scripts/probe_mlp_control.py`; ad hoc single-task loops, batch size 1-4, not the general trainer):
  - **Segmentation** (ChestX-Det, binary "any lesion", Dice at 256px). At 400 steps, ordering across conditions was as expected: C0 0.267 < C1 (self) 0.387 < C2 (dinov2) 0.330 / (siglip) 0.297 < C3 (biomedclip) 0.417 < **C3 (rad_dino) 0.516**. At 1500 steps, C0 0.289, **C3 (rad_dino) 0.552** (0.548 before the projector norm fix, 0.552 after -- alpha dropped from 0.039 to 0.090 and `correction_over_native` from 0.77 to 0.16, i.e. the fix changed what alpha means, not the outcome). But a capacity-matched MLP probe directly on RAD-DINO features, no LLM, already gets **0.550** (1500 steps) -- on segmentation alone, routing through the frozen 4B LLM adds nothing measurable over a capacity-matched probe on the expert features.
  - **VQA** (VQA-RAD yes/no, 800 steps, 3 seeds): majority baseline 0.530, **C0 (no expert) 0.705 ± 0.004**, **C3 (rad_dino) 0.705 ± 0.006** (variance only stabilised after lowering the conditioner's LR 10x; at the base LR it was 0.702 ± 0.022). The MLLM route clears the baseline by a wide, stable margin on a task a standalone encoder+probe cannot attempt at all -- but the expert adds nothing measurable over C0 here either.
  - Net: the frozen-MLLM route's value so far is doing VQA at all (H2), not the expert improving it (H1 is not yet supported by either task at current training budgets).
